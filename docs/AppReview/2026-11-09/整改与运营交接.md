## 提交前必须落实

### 举报与内容安全

1. 用户已确认本人负责审核；上线前仍需确认支持邮箱能接收和回复、能处理紧急举报，并确定实际值守和响应时限。不能仅因添加邮箱就声称审核已投入运行。
2. 已在 Chrome 中确认正确的 Liya Supabase 项目。线上原有举报表为 `liya_social_reports`（社区帖子和用户）、`liya_content_reports`（示例素材）、`liya_video_comment_reports`（媒体评论）。本地已准备审核队列、处理状态、操作记录和社区评论举报；迁移尚未部署，旧线上表不能当作已经具备完整审核流程。
3. 本地迁移准备了公开资料、头像、帖子、附件和评论的人工先审后发，以及私聊单条主动举报；精选素材可限制新文件访问并保留目录排序，新版 App 的预设评论可单独隐藏。具体操作见 `内容审核操作说明.md`。需要验证权限、运营处理、可见性及恢复；旧版 App 不遵循预设评论开关，已签发素材链接和缓存也不能立即收回，不能声称所有内容均已覆盖。
4. 用两个测试账号验证每种内容的举报、拉黑、下架、处理时效、通知和支持邮件收发。社区评论单独举报入口及图片评论举报的服务端策略也应逐项核查；不要只验证帖子举报。
5. 只有流程真实运行并验证后，才能更新 App 内“审核未配置”的提示和协议；重新生成、检查并发布新版本 PDF，再更新 App 使用的 PDF 地址与 ASC 隐私政策链接。

### Apple 登录撤销

1. 目前未保存 Apple 授权码或 token，也未在 Liya 后台配置自动撤销。历史账号删除保持现有成功确认与恢复行为；用户可按 App 提供的 Apple 官方链接手动撤销。
2. 对新账号建立安全的服务端流程：将原生 Apple 登录的授权码安全发送给受认证保护的后台，使用与原生 App ID 匹配的 Apple 签名密钥生成 client secret，验证并交换授权码，验证 Apple 身份与当前 Supabase 用户绑定，安全保存 token，并按 Apple 的 TN3194 管理和撤销。不要把私钥、client secret 或 refresh token 写入 App、仓库或日志。
3. 设计删除与撤销的失败、重试、并发和幂等处理；不能因没有 token 而阻止用户完成账号删除。验证历史账号、取消授权、网络中断和重复请求，确保没有误删或错误撤销其他用户。
4. 已在浏览器确认 Liya 所在 Supabase 项目；自动撤销还需要 Apple Developer 的 Team ID、Key ID 和安全配置的 Sign in with Apple 私钥。尚未配置，也未实施自动撤销。

Apple 参考：[账号删除与 token 撤销 TN3194](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple)、[管理 Sign in with Apple](https://support.apple.com/en-us/102571)、[App Review 1.2](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)。
