# 内容审核隔离验证记录

## 2026-11-09：本机 PostgreSQL 兼容环境

使用 `@electric-sql/pglite` 0.3.14 在内存中创建临时数据库，加载与审核相关的前置迁移和 `20261109064127_liya_moderation_queue.sql`，以模拟的登录角色和三个虚构账号执行测试。数据库随进程退出销毁，没有连接或修改生产数据库。

首轮发现预设评论状态 RPC 的返回列 `position` 未转义，导致迁移语法错误；已修正，重新运行后迁移和下列断言通过：

- 公开资料首次提交、重复 upsert、待审版本隔离、审核通过、过期版本拒绝，以及头像审核、隐藏、恢复和取消共享。
- 帖子和附件在待审及隐藏期间对其他账号不可见；通过或恢复后可见；编辑后的旧审核版本不能误通过。
- 评论待审期间不可见且不产生评论通知，通过后可见并产生通知；图片评论计数不包含其他人的待审评论。
- 评论举报和私聊举报的归属、内容快照校验；非接收者和伪造内容遭权限拒绝，举报状态只返回给举报人。消息测试包含互相关注的数据库约束。
- 精选素材限制与恢复、预设评论限制与恢复，以及普通账号不能调用审核员处置函数。
- 删除测试账号后，其审核内容及对应举报队列的级联清理。

可复现脚本：[moderation_check.mjs](../../../supabase/tests/moderation_check.mjs)。需要 Node.js、npm 和联网安装测试依赖；不会修改项目依赖，也不连接真实服务：

```sh
export LIYA_TEST_HOME="$(mktemp -d)"
npm install --prefix "$LIYA_TEST_HOME" --no-audit --no-fund @electric-sql/pglite@0.3.14
node supabase/tests/moderation_check.mjs
```

## 2026-11-09：本地 Supabase 服务

在独立的 Colima 虚拟机中启动 Supabase CLI 3.0.0 的本地服务，使用虚构的临时账号和文件，通过真实 Auth、PostgREST 和 Storage API 验证；未连接生产数据库。共加载 15 个与审核有关的迁移，包含互相关注和审核迁移。检查通过：

- 两个账号创建及登录、资料首次提交与再次 upsert、审核版本检查和公开资料更新。
- 新帖子及其附件先审；审核前其他账号无法读取帖子或获得附件签名链接，审核后可读取。
- 帖子评论先审、评论举报和举报状态的账号隔离；私聊消息仅在接收者主动举报后进入举报队列，伪造快照和发送者冒充接收者的举报被拒绝。
- 精选素材隐藏后不能再申请签名链接；隐藏前签发的链接仍可访问。预设评论隐藏状态可经 RPC 获取。

测试脚本为 [moderation_integration.mjs](../../../supabase/tests/moderation_integration.mjs)。它需要已经启动的专用本地 Supabase 项目，并只接受 `127.0.0.1:55321`；该脚本创建虚构账号、bucket 和内容，不能用于生产或包含真实数据的环境。测试后已停止该本地项目并删除其测试数据卷，专用 Colima 虚拟机已停止；安装的 Colima、Lima、Docker CLI 和下载的镜像保留在电脑上。

## 覆盖边界

- 这是 PGlite 和本地 SQL 测试，不是真实 Supabase 实例。测试中的 `auth.users`、`auth.uid()`、`storage.objects` 和 Storage 路径函数为简化模型；仅加载相关迁移，不代表整套迁移历史或线上结构一致。互关规则仅加载消息部分，未测试通话触发器。
- 本地 Supabase 已覆盖实际 Auth、PostgREST、Storage 上传、签名和签名链接有效期内的行为；没有测试生产环境的 CDN、Realtime、Edge Functions、客户端构建、运行、旧版本、设备、网络故障或并发事务。账号删除仅测试数据库级级联，没有执行真实删除函数或 Storage 清理。
- 2026-11-09 浏览器中查看的 Liya 线上项目只有 `main` 生产分支。控制台显示预览分支需要升级 Pro，且运行期间持续计费；未创建分支，也未部署迁移。
- 因此，这些结果不能证明线上审核已运行或 App 已可送审。仍需核对生产环境与迁移的实际定义差异，验证完整客户端及线上服务流程，确认实际值守与邮箱，再决定生产发布和新客户端发布顺序。
