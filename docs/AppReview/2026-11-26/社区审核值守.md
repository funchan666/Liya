# Liya 社区审核值守

生产数据库迁移 `20261126090102` 已于 2026 年 11 月 26 日启用。新提交的公开社区资料、共享头像和媒体评论进入人工审核。审核员可以在指定 Liya 项目的 Supabase Dashboard 中处理。值守人需要实际查看内容、安排交接，并确认支持邮箱能收件。

## 查看待处理项

使用有审核权限的数据库操作员身份，在 SQL Editor 中按时间查看队列。以下查询只显示审核所需标识，正文与附件按需打开。

```sql
select kind, content_id, revision, submitted_at
from liya_social_private.moderation_content
where status = 'pending'
order by submitted_at, kind, content_id;

select kind, report_id, created_at
from liya_social_private.moderation_reports
where status = 'pending'
order by created_at, kind, report_id;
```

| 类型 | 查看位置 |
| --- | --- |
| profile | 在 `liya_social_private.moderation_profiles` 按 `owner_id` 读取本次姓名、简介和拟共享头像。在私有 Storage 中按该记录的完整路径核对图片。 |
| media_comment | 在 `public.liya_video_comments` 按 `id` 查看文字与所属的照片或视频。 |
| post、post_comment | 分别按 `id` 查看 `public.liya_posts` 或 `public.liya_post_comments`。有附件时核对每个文件及完整视频。 |
| social 举报 | 在 `public.liya_social_reports` 按举报 ID 查找。成员动态的评论举报带有 `post_id`、`comment_id` 和提交时的正文快照；核对评论 ID 后按 `post_comment` 处置。 私信举报通过同一 `report_id` 关联 `liya_social_private.reported_message_snapshots`，只核对被举报的那条消息。 |
| curated 举报 | 在 `public.liya_content_reports` 按举报 ID 找到被举报的精选媒体或栏目资料。 |
| media_comment 举报 | 在 `public.liya_video_comment_reports` 按举报 ID 查看媒体、快照和理由。`comment_id` 指向成员评论；`preset_key` 指向 Liya 编辑留言，键由媒体 ID、`:starter:` 和留言序号组成。 |

## 处置与回执

- 对待审内容调用 `liya_social_private.review_content(kind, content_id, revision, decision, actor)`。记录当前版本，决定可取 `approved` 或 `rejected`。返回 `false` 时重新读取队列，提交可能已被编辑或处置。
- 已发布的成员内容可用 `hide_content` 隐藏。档案使用 `set_profile_hidden`。精选媒体使用 `set_curated_hidden`。下架单条编辑留言时，按举报中的媒体 ID 和序号调用 `set_curated_starter_hidden`，保留同一动态下的其他评论。这些函数位于 `liya_social_private`。签发过的短时媒体链接可持续至过期。
- 需要下架时先执行内容处置，再使用 `review_report(kind, report_id, decision, actor)` 记录举报结论。成立并处理取 `resolved`，核对后无须处理取 `dismissed`。填写实际值守人代号。
- 用户可在「隐私 → 已提交的举报」查看本人回执。通过支持邮箱提出的问题仍需另行回复。日志与待审材料仅供授权处理人员使用。
