# Liya 锁屏来电接入记录

当前状态：前台通话数据库开关开启；用户选择的 Bundle ID 为 `com.liyalumora.auroramuse`，已写入工程，但 Apple 注册和签名尚未核实。锁屏来电的客户端和服务器代码已准备并部署，在 Apple 推送配置就绪前保持未启用。未编译、未测试、未验证设备或 APNs；不要把密钥值写入源码、日志或聊天。

## 正式配置时需要

1. 在 Apple Developer 核实并注册所选 Bundle ID `com.liyalumora.auroramuse`，确定 Apple Developer Team，给该 App ID 启用 Push Notifications，准备匹配的开发和发布描述文件。工程和 `project.yml` 已使用所选标识；`Liya/Liya.entitlements` 使用 `APS_ENVIRONMENT`（Debug 默认为 `development`，Release 默认为 `production`），实际签名必须与描述文件一致。
2. `APNS_BUNDLE_ID` 已在 Liya 项目的 Supabase Edge Function Secrets 中设置为所选标识。在 Apple Developer 创建或选用具备 APNs 能力的认证密钥，通过安全方式配置剩余的 `APNS_TEAM_ID`、`APNS_KEY_ID` 和 `APNS_PRIVATE_KEY`。`.p8` 私钥不放进 App 或 Git。
3. 核对上述服务端 Bundle ID 与签名包完全一致，并在 Supabase 中启用 `public.liya_voip_config.enabled`、激活 `liya-voip-delivery` Cron。当前数据库配置和定时任务均为未启用；它们只控制锁屏来电，不关闭现有前台通话。
4. 待用户明确授权运行验证后，检查 Debug/sandbox、TestFlight/production 和实际签名环境；确认设备令牌按账号登记与失效处理，来电必须及时上报 CallKit，接听／拒绝／挂断、权限缺失、锁屏、冷启动、背景音频、音视频中断和重连均须真机核验。当前 Debug 选择 sandbox、Release 选择 production；特殊签名方式需按实际 APNs entitlement 调整。

`liya-voip-registration` 以登录用户 JWT 验证设备登记；`liya-voip-delivery` 仅接受数据库创建的一次性高熵任务能力值，不能通过 App 指定任意接收人或推送服务地址。服务端配置未就绪时不会注册或发送推送；两端真实可达性、APNs HTTP/2 和权限隔离尚未验证。

`liya-call-cleanup` 在已接听通话结束、屏蔽或账号删除时排队，通过 LiveKit 服务器 API 移除双方、撤销令牌并清理房间；失败由 Cron 重试。后台任务不依赖 Apple Bundle ID，但调用链与远端实际踢出效果未测试。其任务能力值和设备令牌均存于禁止普通用户读取的表，不能据部署记录推断线上安全验证通过。
